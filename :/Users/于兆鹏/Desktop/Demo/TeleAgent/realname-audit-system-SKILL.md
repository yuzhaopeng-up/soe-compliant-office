# 实名稽核系统 (Real-name Audit System)

## 元数据

| 属性 | 值 |
|------|-----|
| 技能名称 | realname-audit-system |
| 版本 | 1.0.0 |
| 作者 | 于兆鹏 |
| 用途 | 电信实名制工单批量稽核：OCR识别→字段提取→政策比对→证据链验证→PII脱敏→Excel稽核表→PPT报告→归档 |
| 触发关键词 | 实名稽核、实名审核、证件稽核、身份证验证、批量稽核、实名制检查 |
| 调度方式 | phase-orchestrator（9 Phase 强制链式编排） |

---

## 场景描述

电信营业厅/线上渠道办理业务时，需采集用户身份证正反面照片及免冠照。质检团队定期批量稽核这些实名资料，检查是否存在**免冠照缺失、翻拍/模糊证件、签发机关与行政区划不一致、证件过期、非本人签办、信息缺失**等问题。

本技能将稽核全流程自动化：输入图片文件夹 → 输出 Excel 稽核表 + PPT 分析报告，所有 PII 数据脱敏处理，稽核记录归档留存。

---

## 7 种问题类型定义

| 编号 | 问题类型 | 检测逻辑 | 严重等级 |
|------|---------|---------|---------|
| R1 | 免冠照不全 | 免冠照片字段为空/无/缺失，或图片中无人像 | 高 |
| R2 | 翻拍证件照 | 证件照类型=翻拍，或OCR识别到屏幕边框/反光特征 | 高 |
| R3 | 证件照模糊 | OCR置信度<0.7，或关键字段提取失败率>30% | 高 |
| R4 | 证件过期/临期 | 证件有效期<当前日期（过期）；有效期-当前日期<90天（临期） | 过期=高，临期=中 |
| R5 | 行政区划不一致 | 身份证前6位（行政区划码）与签发机关所在区县不匹配 | 高 |
| R6 | 非本人签办 | 姓名与证件姓名不一致，或人脸比对分<阈值（需外部接口） | 高 |
| R7 | 信息字段缺失 | 姓名/证件号/签发机关任一必填字段为空 | 中 |

## Phase 0: 图片批量输入与预处理

### 触发条件
用户提供图片文件夹路径，或明确要求对某目录进行实名稽核。

### 输入
```json
{
  "input_dir": "C:/path/to/images/",
  "batch_id": "AUTO-YYYYMMDD-HHMMSS",
  "supported_formats": ["jpg", "jpeg", "png", "bmp", "pdf"],
  "max_file_size_mb": 20,
  "max_batch_count": 500
}
```

### 处理逻辑
1. 递归遍历 `input_dir`，筛选支持的图片格式
2. 过滤超大文件（>20MB 标记为 R3 模糊候选）
3. 按文件名/子目录名推断工单归属（命名规则：`{姓名}_{证件号后4位}_{日期}.jpg`）
4. 生成预处理清单：文件路径、文件大小、图片尺寸、预估质量等级

### 输出
```json
{
  "batch_id": "AUTO-20260626-140000",
  "total_files": 120,
  "valid_files": 115,
  "skipped_files": 5,
  "skip_reasons": [{"file": "xxx.pdf", "reason": "格式不支持"}, ...],
  "file_list": [
    {
      "file_path": "C:/path/to/images/张三_1234_20260601.jpg",
      "file_size_kb": 850,
      "dimensions": "1920x1080",
      "quality_estimate": "normal",
      "inferred_name": "张三",
      "inferred_id_tail": "1234"
    }
  ]
}
```

### 调用组件
- 文件系统操作（本地）

### 容错规则
- 空目录 → 终止，返回错误提示
- 超过500张 → 分批处理，每批200张
- 命名不规范 → 标记为"未分类"，不阻断后续流程

## Phase 1: OCR 文字识别

### 输入
Phase 0 输出的 `file_list`

### 处理逻辑
1. 逐张图片调用 OCR 引擎，提取文本内容
2. 识别身份证正反面布局（正面：姓名/性别/民族/出生/住址/身份证号；背面：签发机关/有效期）
3. 记录各字段的 OCR 置信度分数
4. 对低置信度字段（<0.7）标记为 R3 候选

### 输出
```json
{
  "batch_id": "AUTO-20260626-140000",
  "ocr_results": [
    {
      "file_path": "C:/path/to/images/张三_1234_20260601.jpg",
      "ocr_text": "姓名 张三 性别 男 民族 汉 出生 1990年01月01日 ...",
      "confidence_avg": 0.92,
      "confidence_per_field": {
        "姓名": 0.98,
        "身份证号": 0.95,
        "签发机关": 0.88,
        "有效期": 0.91
      },
      "low_confidence_fields": [],
      "detected_type": "身份证正面",
      "quality_flags": []
    }
  ]
}
```

### 调用组件
- `xc-doc-parser`（星辰OCR，优先）或 `paddleocr-doc-parsing`（离线备选）

### 容错规则
- OCR 引擎超时 → 切换备选引擎，重试1次
- 单张完全识别失败 → 标记 R7（信息缺失），不阻断批处理
- 置信度全 < 0.5 → 标记 R3（模糊），跳过字段提取

---

## Phase 2: 关键字段提取

### 输入
Phase 1 输出的 `ocr_results`

### 处理逻辑
1. 从 OCR 文本中提取 7 个必填字段：
   - **姓名**：正则 `姓\s*名\s*[：:]\s*(\S{2,4})`
   - **身份证号**：正则 `(\d{17}[\dXx])`，校验位验证
   - **签发机关**：正则 `签发机关\s*[：:]\s*(.+?局)`
   - **有效期起止**：正则 `有效期\s*(\d{4}.\d{2}.\d{2}).*?(\d{4}.\d{2}.\d{2}|长期)`
   - **免冠照片**：检测是否包含独立人像照片
   - **证件照类型**：翻拍/直拍/扫描件
   - **问题分类**：原始标注或自动推断
2. 校验身份证号合法性（18位 + 校验码算法）
3. 对提取失败字段标记为 R7（信息缺失）

### 输出
```json
{
  "batch_id": "AUTO-20260626-140000",
  "extracted_records": [
    {
      "record_id": "REC-001",
      "file_path": "C:/path/to/images/张三_1234_20260601.jpg",
      "fields": {
        "姓名": {"value": "张三", "confidence": 0.98, "source": "ocr"},
        "身份证号": {"value": "360102199001011234", "confidence": 0.95, "source": "ocr"},
        "签发机关": {"value": "南昌市公安局东湖分局", "confidence": 0.88, "source": "ocr"},
        "有效期起": {"value": "2020.01.01", "confidence": 0.91, "source": "ocr"},
        "有效期止": {"value": "2040.01.01", "confidence": 0.91, "source": "ocr"},
        "免冠照片": {"value": "无", "confidence": 1.0, "source": "meta"},
        "证件照类型": {"value": "翻拍", "confidence": 0.85, "source": "ocr+image"},
        "问题分类": {"value": "免冠照不全+翻拍证件照", "confidence": 0.9, "source": "auto"}
      },
      "missing_fields": [],
      "id_number_valid": true
    }
  ]
}
```

### 调用组件
- `info-extractor`（结构化字段提取）
- 正则引擎 + 身份证校验码算法（本地）

### 容错规则
- 身份证号校验失败 → 标记 R7 + id_number_valid=false，仍保留原始值
- 姓名提取失败 → 尝试从文件名推断
- 多个身份证号命中 → 取与签发机关匹配度最高的

## Phase 3: 政策库比对

### 输入
- Phase 2 输出的 `extracted_records`
- 政策规则库（YAML配置文件的内置规则 + 可选外部知识库）

### 内置政策规则
```yaml
policy_rules:
  - rule_id: P01
    name: 实名制六要素
    description: "姓名、证件类型、证件号码、证件有效期、证件照、免冠照必须齐全"
    required_fields: ["姓名", "身份证号", "签发机关", "有效期止", "证件照类型", "免冠照片"]
    violation_maps_to: R7

  - rule_id: P02
    name: 免冠照强制要求
    description: "所有实名业务必须采集免冠照片，缺失即违规"
    check: "免冠照片 != 无 AND 免冠照片 != NULL"
    violation_maps_to: R1

  - rule_id: P03
    name: 翻拍证件拒收
    description: "翻拍/扫描件不可作为有效证件照，必须原拍"
    check: "证件照类型 != 翻拍"
    violation_maps_to: R2

  - rule_id: P04
    name: 证件有效期检查
    description: "证件不得过期，临期90天内需预警"
    check: "有效期止 >= today()"
    warning_check: "有效期止 - today() < 90天"
    violation_maps_to: R4

  - rule_id: P05
    name: 行政区划一致性
    description: "身份证前6位行政区划码必须与签发机关所在区县一致"
    check: "id_prefix_6 == issuing_authority_region_code"
    violation_maps_to: R5

  - rule_id: P06
    name: 照片清晰度标准
    description: "OCR平均置信度 >= 0.7，关键字段置信度 >= 0.6"
    check: "confidence_avg >= 0.7"
    violation_maps_to: R3

  - rule_id: P07
    name: 本人签办核验
    description: "办理人姓名须与证件姓名一致"
    check: "办理人姓名 == 证件姓名"
    violation_maps_to: R6
```

### 处理逻辑
1. 逐条记录匹配 7 条政策规则
2. 生成合规/违规判定结果
3. 对违规项映射到对应问题类型（R1-R7）
4. 标注违规严重等级（高/中/低）

### 输出
```json
{
  "batch_id": "AUTO-20260626-140000",
  "policy_results": [
    {
      "record_id": "REC-001",
      "compliance_checks": [
        {"rule_id": "P01", "result": "pass", "detail": "六要素齐全"},
        {"rule_id": "P02", "result": "fail", "detail": "免冠照片=无", "mapped_issue": "R1", "severity": "高"},
        {"rule_id": "P03", "result": "fail", "detail": "证件照类型=翻拍", "mapped_issue": "R2", "severity": "高"},
        {"rule_id": "P04", "result": "pass", "detail": "有效期至2040.01.01"},
        {"rule_id": "P05", "result": "pass", "detail": "360102↔东湖区一致"},
        {"rule_id": "P06", "result": "pass", "detail": "置信度0.92"},
        {"rule_id": "P07", "result": "pass", "detail": "姓名一致"}
      ],
      "issue_list": ["R1", "R2"],
      "compliance_score": 71.4
    }
  ]
}
```

### 调用组件
- `knowledge-rag`（查询外部政策文档，可选）
- 规则引擎（内置YAML规则，本地执行）

### 容错规则
- 外部知识库不可用 → 降级为纯内置规则
- 行政区划码库缺失 → P05 标记为"待人工复核"

## Phase 4: 证据链交叉验证

### 输入
- Phase 2 的 `extracted_records`
- Phase 3 的 `policy_results`

### 处理逻辑
对每条记录执行 5 维交叉验证：

| 验证维度 | 证据源A | 证据源B | 不一致映射 |
|---------|--------|--------|-----------|
| V1 行政区划一致性 | 身份证前6位→省市区 | 签发机关文本→省市区 | R5 |
| V2 问题特征匹配 | 提取特征（免冠照=无） | 问题分类标签（免冠照不全） | 标注矛盾 |
| V3 OCR置信度 vs 质量标记 | OCR置信度分数 | 图片质量估计 | R3 |
| V4 有效期交叉核验 | 有效期起止日期 | 当前日期 + 政策阈值 | R4 |
| V5 字段完整性校验 | 必填字段集合 | 实际提取字段集合 | R7 |

每维度独立计算置信度（0-1），综合加权：
```
总置信度 = 0.30×V1 + 0.25×V2 + 0.15×V3 + 0.15×V4 + 0.15×V5
```

### 输出
```json
{
  "batch_id": "AUTO-20260626-140000",
  "evidence_results": [
    {
      "record_id": "REC-001",
      "name": "张三",
      "validations": {
        "V1_admin_consistency": {
          "id_prefix": "360102 → 江西省南昌市东湖区",
          "issuing_authority": "南昌市公安局东湖分局 → 东湖区",
          "match": true,
          "confidence": 0.95
        },
        "V2_issue_feature_match": {
          "features": {"免冠照片": "无", "证件照类型": "翻拍"},
          "labeled_issues": ["免冠照不全", "翻拍证件照"],
          "match": true,
          "confidence": 0.98
        },
        "V3_ocr_quality": {
          "ocr_avg_confidence": 0.92,
          "quality_estimate": "normal",
          "match": true,
          "confidence": 0.95
        },
        "V4_expiry_check": {
          "expiry_date": "2040-01-01",
```

### 调用组件
- `evidence-chain`（多源交叉验证 + 冲突检测）

### 容错规则
- 置信度 < 0.7 → 标记"待人工复核"
- 检测到矛盾 → 记录矛盾详情，以高置信度源为准，低置信度源标记存疑
- V1 行政区划码库查不到 → 置信度降为 0.5，标记"待人工复核"

## Phase 5: PII 脱敏处理

### 输入
Phase 2-4 的全部输出数据

### 脱敏规则

| 数据类型 | 脱敏方式 | 示例 |
|---------|---------|------|
| 身份证号 | 保留前6后4，中间8位用 `*` 替代 | 360102\*\*\*\*\*\*\*\*1234 |
| 姓名 | 保留姓，名用 `*` 替代 | 张\* |
| 手机号 | 保留前3后4，中间4位用 `*` 替代 | 138\*\*\*\*5678 |
| 住址 | 保留省市区，后用 `***` 替代 | 江西省南昌市东湖区\*\*\* |
| 免冠照片/人像 | 高斯模糊处理（半径15px） | — |
| 身份证照片 | 正面遮挡证件号中间8位；背面遮挡有效期 | — |

### 处理逻辑
1. 对所有文本字段执行脱敏替换
2. 对图片执行遮挡/模糊处理
3. 生成脱敏映射表（仅存于内存，不落盘、不出输出）
4. 验证脱敏后数据不包含完整PII

### 输出
```json
{
  "batch_id": "AUTO-20260626-140000",
  "desensitized_records": [
    {
      "record_id": "REC-001",
      "fields_masked": {
        "姓名": "张*",
        "身份证号_masked": "360102********1234",
        "身份证号_hash": "sha256:abc123...",
        "签发机关": "南昌市公安局东湖分局",
        "免冠照片": "无（原值=无，无需脱敏）",
        "证件照类型": "翻拍",
        "有效期止": "2040-01-01"
      },
      "images_processed": {
        "id_front": "desensitized/REC-001_front_masked.jpg",
        "id_back": "desensitized/REC-001_back_masked.jpg",
        "photo": null
      },
      "pii_scan_passed": true
    }
  ],
  "mask_mapping": "MEMORY_ONLY_NOT_PERSISTED"
}
```

### 调用组件
- `security-guard`（PII检测 + 脱敏规则校验）
- 图片处理库（Pillow/OpenCV，本地）

### 安全铁律
1. **脱敏映射表严禁落盘** — 仅存在于本次执行内存中
2. **原始图片严禁复制到输出目录** — 仅脱敏后版本可输出
3. **脱敏后二次扫描** — 全量正则扫描，确保无完整证件号/手机号残留
4. **审计日志记录脱敏操作** — 记录"何时对何字段执行了何种脱敏"，不含原始值

## Phase 6: 生成 Excel 稽核表

### 输入
- Phase 5 的 `desensitized_records`
- Phase 3 的 `policy_results`
- Phase 4 的 `evidence_results`
- 原始图片（脱敏后嵌入）

### Excel 结构设计

**Sheet 1: 稽核明细表**

| 列 | 内容 | 格式 |
|----|------|------|
| A | 序号 | 居中 |
| B | 姓名（脱敏） | 张\* |
| C | 身份证号（脱敏） | 360102\*\*\*\*\*\*\*\*1234 |
| D | 签发机关 | — |
| E | 有效期止 | 日期格式 |
| F | 免冠照片 | 有/无 |
| G | 证件照类型 | 直拍/翻拍/扫描 |
| H | 问题分类 | R1+R2 格式 |
| I | 严重等级 | 高（红）/中（黄）/低（绿） |
| J | 合规评分 | 0-100，条件格式 |
| K | 验证置信度 | 0-1 |
| L | 证件照（脱敏缩略图） | 嵌入图片 80x50px |
| M | 处理建议 | 整改/重采/人工复核 |

**Sheet 2: 统计汇总表**

| 统计项 | 公式/逻辑 |
|--------|----------|
| 总工单数 | COUNTA |
| 合规工单数 | COUNTIF(合规评分=100) |
| 违规工单数 | 总-合规 |
| 合规率 | 合规/总 |
| R1-R7 各类问题数量 | COUNTIF 逐项 |
| 严重等级分布 | 高/中/低 计数 |
| 平均置信度 | AVERAGE |

**Sheet 3: 异常清单**
- 仅筛选严重等级=高 或 置信度<0.7 的记录
- 含详细处理建议和截止日期

### 输出

## 全局安全铁律

| 编号 | 铁律 | 说明 |
|------|------|------|
| G1 | PII严禁明文落盘 | 所有输出文件（Excel/PPT/JSON）中身份证号、手机号必须脱敏 |
| G2 | 脱敏映射严禁持久化 | 映射表仅在内存中存在，进程结束即销毁 |
| G3 | 原始图片严禁外泄 | 输出目录仅含脱敏后图片，原始图片路径仅记录不复制 |
| G4 | 审计日志全程留痕 | 每个Phase的输入/输出摘要、耗时、异常均记录 |
| G5 | 单条记录可追溯 | 从归档记录可反向追溯到原始文件路径和批次号 |
| G6 | 高风险自动熔断 | 单批次高风险率>30% → 暂停自动流程，触发人工确认 |

## 全局容错与降级机制

| 故障场景 | 降级策略 |
|---------|---------|
| OCR引擎不可用 | 切换备选引擎；双引擎不可用 → 标记全部R7，输出"待人工OCR" |
| 行政区划码库缺失 | P05/V1 标记"待人工复核"，置信度降为0.5 |
| Excel生成失败 | 降级输出CSV文件 |
| PPT生成失败 | 降级输出Markdown格式报告 |
| 归档写入失败 | 缓存至临时目录，标记"待归档"，下次启动自动补归档 |
| 单条记录处理异常 | 跳过并记录到异常清单，不阻断批处理 |
