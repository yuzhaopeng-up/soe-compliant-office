# 6维检查合规

对输入内容按6个维度进行系统性合规审查，生成结构化检查报告。

## 检查流程

1. 接收输入内容（文本、文档、方案、流程描述等）
2. 按6个维度逐一检查（详见 [references/checklist.md](references/checklist.md)）
3. 汇总检查结果，标注不合格项
4. 生成合规检查报告（默认DOCX格式）

## 6个检查维度概览

| 维度 | 核心检查点 |
|------|-----------|
| 场景合规 | 触发场景明确、条件清晰、范围界定 |
| 参数合规 | 命名规范、类型明确、缺省合理、校验完备 |
| 逻辑合规 | 步骤清晰、单一职责、顺序正确、异常覆盖 |
| 输出合规 | 结构完整、格式统一、含未确认项、可追溯 |
| 安全合规 | 权限最小化、无高危操作、敏感信息保护、只读 |
| 归档合规 | 路径明确、命名规范、格式统一、可追溯 |

## 输入参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| content | 文本 | 是 | 无 | 待检查的文档/方案/流程/规则内容 |
| content_type | 枚举 | 否 | "通用" | 内容类型：通用/方案/流程/规则/合同/制度 |
| output_format | 枚举 | 否 | "DOCX" | 输出格式：DOCX/Markdown |
| check_dimensions | 多选 | 否 | 全部6维 | 指定检查维度（可跳过部分维度） |

## 执行步骤

### Step 1：内容解析

- 提取输入内容的核心要素
- 识别内容类型（方案/流程/规则/合同/制度/其他）
- 确定检查范围（全6维或用户指定维度）

### Step 2：逐维检查

对每个指定维度，按 [references/checklist.md](references/checklist.md) 中的检查清单逐项审查：

1. 读取该维度的检查项和通过条件
2. 对照输入内容判定每项是否合格
3. 不合格项记录原因和整改建议
4. 给出该维度的整体合格率

### Step 3：汇总评级

- 统计各维度合格率
- 按严重程度对不合格项分级：**严重**（安全/逻辑维度不合格）、**一般**（参数/输出维度不合格）、**轻微**（场景/归档维度不合格）
- 给出整体合规等级：
  - A级：全维度合格
  - B级：轻微不合格项 ≤ 2
  - C级：一般不合格项 ≤ 2，无严重项
  - D级：有严重不合格项

### Step 4：生成报告

按输出模板格式化结果。

## 安全规则

- 本技能执行只读操作，不修改任何原始输入内容
- 不输出原始文档中的敏感信息（身份证号、密码、密钥等），替换为 `[已脱敏]`
- 检查结果仅供参考，不替代正式合规审计
- 不对外传输检查内容，所有处理在本地完成

## 央国企特色

### SOE-Unique Compliance Requirements Addressed

本Skill直接解决央国企独有的合规需求：

| SOE需求 | 对应检查维度 | 检查要点 |
|---------|-------------|---------|
| 三重一大集体决策 | 逻辑合规 | 重大决策是否有集体审议步骤、表决记录是否完整 |
| 党委前置审议 | 场景合规 | 涉及党建/人事/重大投资是否有党委前置标记 |
| 穿透式监管 | 输出合规 | 输出是否可穿透追溯至源头、中间层是否可还原 |
| 全量归档+永久保管 | 归档合规 | 路径是否满足DA/T标准、保管期限是否声明 |
| GB/T 9704红头文件 | 输出合规 | 格式是否符合国标、文号/密级/紧急程度是否齐全 |
| 首席合规官审核 | 安全合规 | 高风险文档是否需合规官签审、签审链是否完整 |

### SOE Compliance Rating Mapping

| 本Skill评级 | SOE内控对应 | 典型处置 |
|------------|-----------|---------|
| A级 | 合规通过 | 可直接签发 |
| B级 | 基本合规 | 需补充轻微项后签发 |
| C级 | 存在风险 | 需整改后重新审查 |
| D级 | 不合规 | 禁止签发，必须全面整改 |

## 输出归档

- 保存路径：`compliance-check/YYYY-MM-DD_[主题].docx`
- 命名规则：日期_内容主题，主题取自输入内容的标题或核心关键词
- 默认格式：DOCX（当 output_format 为 Markdown 时生成 .md）
