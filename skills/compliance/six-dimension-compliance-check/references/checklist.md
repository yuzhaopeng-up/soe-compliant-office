# 6维合规检查清单

## 维度1：场景合规

检查对象是否明确了触发场景和触发条件。

| 检查项 | 通过条件 | 不合格示例 |
|--------|----------|------------|
| 触发场景是否明确 | 能用一句话描述何时应执行 | "需要的时候"（过于模糊） |
| 触发条件是否清晰 | 条件可判定、无歧义 | "必要时"（无法判定） |
| 适用范围是否界定 | 明确了适用与不适用的边界 | 无范围说明 |
| 排除条件是否声明 | 声明了不应触发的场景 | 无排除条件 |

## 维度2：参数合规

检查输入参数的规范性。

| 检查项 | 通过条件 | 不合格示例 |
|--------|----------|------------|
| 参数命名是否规范 | 采用统一命名规范（snake_case / camelCase） | 混用多种风格 |
| 参数类型是否明确 | 每个参数声明了类型（文本/数值/枚举/日期等） | 未指定类型 |
| 必填/可选是否标注 | 每个参数标注了必填或可选 | 标注不全 |
| 默认值是否合理 | 可选参数有合理默认值 | 可选参数无默认值 |
| 参数校验规则是否存在 | 关键参数有取值范围或格式约束 | 无校验 |

## 维度3：逻辑合规

检查执行步骤的合理性和规范性。

| 检查项 | 通过条件 | 不合格示例 |
|--------|----------|------------|
| 步骤是否清晰 | 每步用祈使句描述，可独立执行 | 步骤含糊或嵌套 |
| 是否符合单一职责 | 每步只完成一个目标 | 一步内含多个不相关操作 |
| 步骤顺序是否正确 | 依赖关系正确，无逻辑回环 | 在数据来源确定前引用数据 |
| 异常处理是否覆盖 | 关键步骤有失败后的处理方案 | 无异常处理 |
| 是否存在冗余步骤 | 无重复操作 | 多次执行相同查询 |

## 维度4：输出合规

检查输出结构和内容的完整性。

| 检查项 | 通过条件 | 不合格示例 |
|--------|----------|------------|
| 输出结构是否完整 | 包含所有必需的输出段 | 缺少结论段 |
| 格式是否统一 | 输出遵循统一模板 | 同类信息格式不一致 |
| 是否含未确认项 | 明确标注了无法确认或存疑的信息 | 未确认项混入确认项 |
| 输出可追溯性 | 关键结论可追溯到输入依据 | 结论无法溯源 |
| 输出分级是否合理 | 按严重程度/优先级分级 | 所有项平铺无优先级 |

## 维度5：安全合规

检查权限控制和风险防范。

| 检查项 | 通过条件 | 不合格示例 |
|--------|----------|------------|
| 权限是否最小化 | 仅申请完成任务所需的最小权限 | 申请了无关权限 |
| 是否存在高危操作 | 无删除、覆写、提权等不可逆操作 | 含删除原始数据步骤 |
| 敏感信息是否保护 | 不输出身份证号、密码等敏感信息 | 明文输出敏感数据 |
| 操作是否可审计 | 关键操作有日志记录 | 无操作留痕 |
| 是否只读 | 检查过程不修改原始输入 | 检查时修改了源文件 |

## 维度6：归档合规

检查结果保存和归档的规范性。

| 检查项 | 通过条件 | 不合格示例 |
|--------|----------|------------|
| 保存路径是否明确 | 声明了输出文件的保存位置 | 未指定路径 |
| 文件命名是否规范 | 遵循统一的命名规则（如日期_主题） | 随意命名 |
| 归档格式是否统一 | 指定了输出格式（DOCX/PDF等） | 格式不确定 |
| 是否支持历史追溯 | 保留版本或时间戳信息 | 无版本信息 |
| 存储是否安全 | 敏感结果不在公开路径保存 | 结果保存在公开目录 |
