### 场景：向管理层通知群发送业务风险预警消息

**输入参数：**
```

operation_target: 管理层通知群(12人)
operation_content: "【业务风险预警】Client-A（某制造企业）本月无新增合同，年度经营数据存在风险，建议3日内回访。"
```

## 课堂脚本

### 1. 开场话术

"不是AI自由执行，而是人在回路——普通Skill直接操作，高级Skill先预览、再确认、后执行、全留痕"

### 2. 演示步骤

1. 填写操作请求（发送群消息 + 管理层通知群 + 含敏感内容）
2. 运行 Skill → 展示风险等级自动评估为 L4
3. 逐条讲解风险提示（为什么是L4？哪些触发了升级？）
4. 让学员选择确认选项 → 展示 [1] 需输入 CONFIRM 的强制确认
5. 展示执行记录和归档内容 → 强调脱敏和 append-only

### 3. 互动提问

"如果我选[3]降级执行，'群发12人'改成什么更安全？"
→ 引导学员理解：群发→私发给直接负责的业务经理（可能2-3人）

### 4. 技术爆点

- Security-Guard 的 L1-L5 分级如何自动生效（触发条件 → 自动升级）
- 归档记录的 append-only 不可篡改特性
- 敏感内容在审批单中可见、归档时脱敏的双重策略

## 学员指南

1. **修改 operation_type** 为不同类型，观察风险等级变化
   - 发送群消息 → L2-L4
   - 修改客户数据 → L3-L4
   - 删除业务记录 → L5

2. **尝试"删除业务记录"**，观察 L5 极高风险的审批要求
   - 必须确认 + 必须 requires_2fa
   - 不启用2fa时的拒绝提示

3. **在 operation_content 中加入个人信息**
   - 手机号（如 13812345678）→ ⚠️ 手机号
   - 身份证号 → ⚠️ 身份证号
   - 观察敏感内容自动标注

4. **选择 [3] 降级执行**，观察降级后的操作目标变化
   - 群发12人 → 私发2-3人
   - 对比执行记录中的差异

5. **查看归档记录**，验证完整性
   - 操作人、时间、选择项、结果
   - 敏感信息是否已脱敏
   - 日志编号格式 APR-YYYYMMDD-NNN

## 自查清单

- [ ] 能否正确评估不同操作类型的风险等级（L1-L5）
- [ ] 能否识别操作内容中的敏感信息并标注 ⚠️
- [ ] 审批单是否完整展示了操作预览、风险提示、4个确认选项
- [ ] L4+ 风险是否强制要求人工确认
- [ ] 确认后是否生成了带日志编号的执行记录
- [ ] 归档记录是否包含完整的审批链（操作人/时间/选择/结果）
- [ ] 选择 [4] 取消时是否正常归档而非报错
- [ ] 脱敏数据在归档时是否正确处理
