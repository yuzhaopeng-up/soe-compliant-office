# 会议纪要输出格式与提取指导

## 提取字段定义

### 必需字段

| 字段 | JSON key | 说明 | 提取要点 |
|------|----------|------|----------|
| 会议名称 | `title` | 会议主题或名称 | 从开头/标题/邮件主题中提取 |
| 会议时间 | `time` | 日期和起止时间 | 注意区分"开会时间"与"日期"，补全年份 |
| 会议地点 | `location` | 线下会议室或线上链接 | 线上会议标注平台名+链接 |
| 参会人员 | `participants` | 出席人员列表 | 含姓名和角色(主持人/记录人/参会人) |
| 决议事项 | `decisions` | 会议达成的共识决议 | 仅提取明确确认的决议，排除讨论中未定内容 |
| 待办任务 | `action_items` | 需跟进执行的事项 | 必含任务描述、负责人、截止日期 |

### 可选字段

| 字段 | JSON key | 说明 |
|------|----------|------|
| 缺席人员 | `absent` | 未出席人员 |
| 其他备注 | `notes` | 不属于上述分类的补充信息 |

## 提取规则

### 时间的识别与标准化

1. 识别形式：`1月15日下午2点`、`2025/01/15 14:00`、`下周三3点-5点`、`明天上午10点`
2. 标准化格式：`YYYY-MM-DD HH:MM-HH:MM`（如 `2025-01-15 14:00-16:00`）
3. 相对时间转绝对时间时需结合上下文判断
4. 若原文仅给日期无时间，标注"具体时间未指明"

### 参会人员提取

1. 区分角色：主持人、记录人、参会人
2. 若原文仅列姓名无角色，默认角色为"参会人"
3. 人名识别线索：签到表、"出席"、"参加"、"列席"等关键词后的人名

### 决议事项提取

1. 关键线索词："决定"、"通过"、"确认"、"同意"、"批准"
2. 排除"建议"、"考虑"、"可能"等不确定性表述——这些归入待办或备注
3. 每条决议应为一个完整、独立、可执行的事项
4. 编号从1开始连续编号

### 待办任务提取

1. 关键线索词："需要"、"负责"、"跟进"、"落实"、"完成"、"提交"
2. 每条任务需尽可能提取：
   - `task`：任务描述（必填）
   - `assignee`：负责人（必填，无法确定时标注"待分配"）
   - `deadline`：截止日期（有则填，无则标注"待定"）
   - `status`：初始状态默认为"待启动"
3. 编号从1开始连续编号
