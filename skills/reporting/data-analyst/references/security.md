## 脱敏规则

### 禁止明文输出的数据类型

| 数据类型 | 脱敏方式 | 示例 |
|----------|----------|------|
| 手机号 | 中间4位替换为**** | 138****5678 |
| 客户姓名 | 用"客户A""客户B"代替 | 客户A |
| 身份证号 | 保留前3后4，中间* | 360***********1234 |
| 详细地址 | 仅保留到下属单位 | XX单位*** |
| 业务账号 | 中间替换为**** | KD****8901 |

### 脱敏执行原则

1. 在分析过程中，原始数据内存中可用，但**输出时**必须脱敏
2. insights / anomalies / recommendations 中不得出现明文敏感信息
3. 若用户传入的数据本身含敏感字段，标注"原始数据含敏感字段，输出已脱敏"

### 脱敏检测流程

```
对输出中每个字符串值:
  1. 匹配手机号正则(/^1[3-9]\d{9}$/) → 脱敏
  2. 匹配身份证号正则(/^\d{17}[\dXx]$/) → 脱敏
  3. 若字段名含"姓名""手机""电话""证件""地址""账号" → 脱敏
```

## 聚合规则

### 默认聚合层级

分析结果默认按以下层级聚合，不展示单客户明细：

- 部门/单位级（如：XX部门、YY部门）
- 下属单位级（如：XX单位A、YY单位B）
- 业务类型级（如：设备故障、重大项目、营销活动）

### 单客户明细展示条件

仅在以下条件同时满足时允许展示单客户明细：
1. 用户明确要求查看明细
2. 明细数据已完成脱敏处理
3. 输出中标注"以下为脱敏后客户级明细"

### 禁止展示的内容

- 任何可直接定位到自然人的组合信息
- 手机号 + 故障地址的组合
- 客户姓名 + 身份证号的组合

## 审计日志

### 必须记录的内容

每次分析执行后，记录以下审计信息：

| 记录项 | 说明 | 示例 |
|--------|------|------|
| 输入字段摘要 | dataset 包含哪些字段 | `[部门, 业务量, 处理时长]` |
| 数据行数 | dataset 的行数 | 150 |
| 分析模式 | 使用的 analysis_mode | `insight` |
| 输出摘要 | status + insight数量 | `success, 4条洞察` |
| 异常记录 | 触发了哪些异常 | `E003: 时间格式混乱` |
| 脱敏动作 | 脱敏了哪些字段 | `手机号已脱敏` |

### 日志格式

```
[AUDIT] timestamp | mode=insight | rows=150 | fields=[部门,业务量,处理时长] | status=success | insights=4 | anomalies=0 | errors=[] | masked=[手机号]
```

## 权限要求

### 最小权限原则

1. 本 Skill 仅读取用户传入的 dataset，不主动访问外部数据源
2. 不修改任何原始数据
3. 不将分析数据发送到外部服务
4. 所有计算在本地完成

### 权限不足处理

若分析过程中需要访问额外数据（如同期对比的历史数据），而该数据不可用：
1. 不自动获取，向用户说明需要额外数据
2. 在 next_actions 中建议用户提供补充数据
3. 不因权限不足而终止已有数据的分析，降级为 partial 即可
