# 上线前自查清单

## 使用方法

逐项检查，全部通过后方可标记为可交付/可上线测试。

---

## 1. 数据字段检查

| # | 检查项 | 通过标准 | 通过? |
|---|--------|----------|-------|
| 1.1 | dataset 参数可接收 JSON 数组 | 传入有效 JSON 数组后 status=success | ☐ |
| 1.2 | dataset 参数可接收表格摘要（文本表格） | 传入文本表格后可正确解析 | ☐ |
| 1.3 | dataset 为空时返回 status=error | 空/非数组/undefined → error | ☐ |
| 1.4 | metrics 字段不存在时返回缺失列表 | 返回 missing_fields 含缺失字段名 | ☐ |
| 1.5 | dimensions 可选参数缺失时仍可执行 | 不传 dimensions → 维度拆解跳过，不报错 | ☐ |
| 1.6 | time_field 格式混乱时降级处理 | 混合格式 → trends 为空，status=partial | ☐ |
| 1.7 | 数值字段含文本时跳过非数值行 | 跳过条数标注在 missing_fields | ☐ |

## 2. 分析逻辑检查

| # | 检查项 | 通过标准 | 通过? |
|---|--------|----------|-------|
| 2.1 | summary 模式仅输出基础统计 | 不含 trends/anomalies/insights | ☐ |
| 2.2 | trend 模式输出趋势方向 | 含 direction 和 change_rate | ☐ |
| 2.3 | anomaly 模式正确识别异常项 | 超 2σ 或超自定义阈值 → 异常 | ☐ |
| 2.4 | comparison 模式输出维度对比 | 含各维度占比和 TOP/BOTTOM | ☐ |
| 2.5 | insight 模式执行完整7步 | 全部字段非空 | ☐ |
| 2.6 | 每条洞察含三段式结构 | what/why_matters/suggestion 非空 | ☐ |
| 2.7 | 每条异常含判断依据 | reason 字段含具体阈值或统计偏离值 | ☐ |
| 2.8 | 每条建议可被执行 | 建议含具体动作而非只说"加强管理" | ☐ |
| 2.9 | 数据不足时标注风险 | confidence < 0.3 时有明确警告 | ☐ |
| 2.10 | threshold_config 不合理时回退 | upper < lower → 使用 2σ 规则 | ☐ |

## 3. 异常规则检查

| # | 检查项 | 通过标准 | 通过? |
|---|--------|----------|-------|
| 3.1 | dataset 为空 → status=error | 返回错误原因 | ☐ |
| 3.2 | 指标字段不存在 → status=error | 列出缺失字段 | ☐ |
| 3.3 | 时间格式混乱 → status=partial | 跳过趋势分析 | ☐ |
| 3.4 | 数据量 < 10 → confidence 上限 0.3 | 标注样本过小 | ☐ |
| 3.5 | threshold_config 不合理 → 回退 | 不因配置错误崩溃 | ☐ |
| 3.6 | 数值字段混入文本 → 跳过 | 不因类型错误崩溃 | ☐ |

## 4. 脱敏检查

| # | 检查项 | 通过标准 | 通过? |
|---|--------|----------|-------|
| 4.1 | 输出中无明文手机号 | 所有手机号已 **** 脱敏 | ☐ |
| 4.2 | 输出中无客户真实姓名 | 用"客户X"替代 | ☐ |
| 4.3 | 输出中无身份证号 | 保留前3后4 | ☐ |
| 4.4 | 输出中无详细地址 | 仅到下属单位 | ☐ |
| 4.5 | 默认聚合到部门/单位/业务类型 | 不展示单客户明细 | ☐ |
| 4.6 | 演示数据无真实客户信息 | 所有示例均为虚构 | ☐ |

## 5. 可解释性检查

| # | 检查项 | 通过标准 | 通过? |
|---|--------|----------|-------|
| 5.1 | 每条洞察引用具体数值 | what 字段含数字 | ☐ |
| 5.2 | 每条异常引用阈值或统计值 | reason 字段含判断依据 | ☐ |
| 5.3 | 每条建议可被业务人员理解 | 无技术黑话 | ☐ |
| 5.4 | confidence 计算可追溯 | 基于数据量/空值率/完整度 | ☐ |
| 5.5 | 降级原因可理解 | missing_fields/next_actions 有说明 | ☐ |

## 6. 多Agent编排检查

| # | 检查项 | 通过标准 | 通过? |
|---|--------|----------|-------|
| 6.1 | pipeline-phases.md 存在且5个Phase定义完整 | 每个Phase含完整prompt模板和输出契约 | ☐ |
| 6.2 | P1质检失败整条流水线终止 | terminate_on_error=true, E001/E002 → 终止 | ☐ |
| 6.3 | P3/P4条件跳转正确 | 无time_field时P3跳过, mode不含anomaly时P4跳过 | ☐ |
| 6.4 | Phase间数据传递格式明确 | 每个Phase的输入来源和输出key在pipeline-phases.md中有定义 | ☐ |
| 6.5 | pipeline_config可按analysis_mode动态构造 | summary=3Phase, trend=4Phase, anomaly=4Phase, comparison=5Phase, insight=5Phase | ☐ |
| 6.6 | 降级策略可执行 | sub-Agent失败→当前Agent执行, 连续2次降级→全降级 | ☐ |
| 6.7 | pipeline_trace在输出中完整 | 记录phases_completed/skipped/fallback_used/execution_mode | ☐ |
| 6.8 | 5个角色身份完整 | 每个角色含代号/职责/禁止行为/输入输出规格 | ☐ |

## 7. 可交付/可复用/可上线测试

| # | 检查项 | 通过标准 | 通过? |
|---|--------|----------|-------|
| 7.1 | 拿来即用 | 无需额外配置即可分析典型场景 | ☐ |
| 7.2 | 可复制改造 | 参数化设计，改 metrics/dimensions 即可复用 | ☐ |
| 7.3 | 适合课堂演示 | 有演示数据，多Agent协作过程可视化，步骤清晰 | ☐ |
| 7.4 | 非空壳文档 | 每个Phase的prompt可直接注入数据执行 | ☐ |
| 7.5 | 7个典型场景全覆盖 | 演示数据覆盖全部 7 个场景 | ☐ |
| 7.6 | 多Agent与单Agent可切换 | phase-orchestrator不可用时自动降级为单Agent执行 | ☐ |

---

**判定标准**：
- 全部 ☐ 打 ☑ → 可交付、可上线测试
- 4.x 脱敏检查任一不通过 → **禁止上线**
- 2.x 分析逻辑任一不通过 → **需修复后重新检查**
- 6.x 多Agent编排任一不通过 → **需修复后重新检查**
- 7.x 可交付检查任一不通过 → **需补充后重新检查**
