## 1. 课堂 3 分钟演示脚本

### 第 1 分钟：为什么一线最容易上手

**演示口诀**："贴数据、选模板、出报告——三步搞定。"

**演示动作**：

1. 打开 TeleAgent，在对话框输入：
   ```
   帮我生成一份业务异常日报。输入数据：2026-07-01 XX分公司业务系统异常 128 件，已处理 116 件，未处理 12 件，超时 3 件。主要问题为老旧设备故障、雨天机房进水。明日计划完成遗留业务记录并复盘超时原因。
   ```
2. 指出：只粘贴了一段文字，没有格式要求也能识别。

**关键话术**：
> "你不需要学任何编程，只需要把你每天写在笔记本上的那段话粘贴进来。Report-Generator 会自动提取数字、识别问题、生成报告。"

---

### 第 2 分钟：如何替换模板

**演示动作**：

1. 展示上一步生成的日报结果。
2. 修改输入，加上 `template_style` 和 `tone`：
   ```
   帮我生成周报。报告类型 weekly，语气正式，模板风格 standard。
   输入数据：2026-06-22~06-28 XX单位运维班组累计接单 342 件...
   ```
3. 对比两种输出的结构差异，指出报告类型变了，模板自动切换。

**关键话术**：
> "日报、周报、会议纪要、问题复盘、客户汇报——5 种模板内置好了。你只需要改 `report_type` 这一个词。模板里的章节、表格、格式全部自动适配。"

---

### 第 3 分钟：如何避免 AI 编造数据 & 接入上游组件

**演示动作**：

1. 指出生成报告中的 `missing_fields` 和 `confidence` 字段：
   > "看到 `missing_fields: []` 和 `confidence: 0.95` 了吗？这说明数据基本齐全。如果输入缺少关键信息，系统会明确标注缺失，而不是编造。"
2. 故意删掉一段数据再生成：
   ```
   输入数据：XX分公司业务系统异常 128 件，已处理 116 件。（删掉了超时和问题）
   ```
3. 展示 `missing_fields` 变为 `["未处理业务量", "超时业务量", "主要问题"]`，`confidence` 降至 0.6。

4. 展示如何接入上游组件：
   > "你可以把 Info-Extractor 的提取结果或 Data-Analyst 的分析结论作为 input_data 直接传进来——它们输出的结构化 JSON 就是这个组件最好的输入。"

**关键话术**：
> "三个组件接力：Info-Extractor 把原始消息变成结构化字段 → Data-Analyst 做分析出结论 → Report-Generator 把结论写成报告。一个人，三步，完成从原始数据到可交付报告的全流程。"

## 2. 学员操作指南

> 一线学员照做即可，6 步完成一份报告。

### 步骤 1：选择报告类型

在 TeleAgent 对话框中告诉系统你要生成什么类型的报告：

| 你想做的 | 告诉系统 |
|---------|---------|
| 每天的工作汇报 | `report_type: daily` |
| 一周的工作总结 | `report_type: weekly` |
| 开完会做纪要 | `report_type: meeting_minutes` |
| 出了问题做复盘 | `report_type: issue_review` |
| 给客户做汇报 | `report_type: customer_brief` |

> 也可以直接说"帮我生成一份日报"，系统会自动识别。

---

### 步骤 2：粘贴数据或摘要

把你手头的数据、业务信息、会议笔记直接粘贴进去。

**可以粘贴的格式**：
- 一段文字（最常见）
- 关键数字列表
- 从 Excel 复制的表格文字
- 从飞书/企微复制的工作记录

**示例**：
```
input_data: 2026-07-01 XX分公司业务系统异常 128 件，已处理 116 件，未处理 12 件，超时 3 件。主要问题为老旧设备故障、雨天机房进水。明日计划完成遗留业务记录并复盘超时原因。
```

> 不需要提前整理格式，系统会自动提取关键信息。

---

### 步骤 3：选择模板和语气（可选）

| 参数 | 选项 | 说明 |
|-----|------|-----|
| `template_style` | `one_page` / `standard` / `brief` | 一页纸简报 / 标准模板 / 简要版 |
| `tone` | `正式` / `简洁` / `汇报型` / `客户友好型` | 语气风格 |
| `audience` | 班组长 / 部门领导 / 客户经理 / 客户方 | 报告看什么人 |
| `max_length` | 数字，如 500 | 最多多少字 |

> 不填也可以，系统会用默认值。

---

### 步骤 4：生成报告

点击发送，等待系统生成。正常 10~30 秒出结果。

---

### 步骤 5：检查缺失字段和风险提示

生成后重点看 3 个地方：

1. **`missing_fields`**：是否有标注缺失的字段？有则补充数据后重新生成。
2. **`confidence`**：
   - 0.8 以上：数据较完整，可直接使用。
   - 0.5~0.8：部分数据缺失，建议补充后使用。
   - 0.5 以下：关键数据严重缺失，不建议直接使用。
3. **`risks`**：是否有风险提示？有则确认是否需要升级处理。

---

### 步骤 6：复制到实际工作场景中使用

- **飞书/企微**：复制 `report_body` 的 Markdown 文本，粘贴即可。
- **Word 文档**：复制后粘贴到 Word，格式自动保留。
- **PPT 备注**：复制纯文本版本到 PPT 备注栏。
- **邮件**：复制纯文本版本作为邮件正文。

> 对外报告（特别是给客户的）务必人工复核后再发送。

---

## 常见问题

| 问题 | 回答 |
|-----|------|
| 我的数据很乱怎么办？ | 直接粘贴，系统会自动提取。如果太乱，可以先用 Info-Extractor 整理。 |
| 报告里有数字我输入时没提？ | 不应该出现。如果发现编造的数字，检查 `confidence` 是否偏低，并补充原始数据。 |
| 想改标题怎么办？ | 生成后直接修改 `report_title` 即可，或在输入时说明你想要的标题。 |
| 模板里的章节想增删？ | 在输入里说明"增加 XX 章节"或"去掉 XX 部分"，系统会调整。 |
| 对外给客户用安全吗？ | 客户汇报模板自带脱敏和人工复核提示，但最终仍需人工确认后才能发送。 |
| 能不能把上游组件结果直接接入？ | 可以。Info-Extractor 输出的 JSON 和 Data-Analyst 的分析结论可以直接作为 `input_data` 传入。 |
